| D11 | Finger soccer in-match "تغییر ترکیب": the side to play changes formation at once on its kickoff shot (its turn, aim phase, no shot since the kickoff); any other time the pick is stored and used from the next kickoff. Online it is a logged `{'a':'form','side','form'}` move, applied by both phones in log order (the sender waits out a goal pause first) | Only the side to play can move its discs, so the change can never race the opponent's shot; matches the reference button at kickoff | — |
| D12 | Finger soccer calibration: reference team powers (Japan 2, Starbucks 15, PSG/Adidas/Kakero 10, Australia 5, read from the reference team-select UI) are used ONLY to normalise measured speeds (`kBmRefPower`, `BmEngine.refStrikeOf`); ANIX team stats in `kBmTeamDefs` stay as they are | The owner's note: power differs per team in the recordings; the "Japan 2 / PSG 10" stat edit (6af40ef) was reverted | — |
| D13 | Finger soccer v3 "lighter discs": only the ball-strikes-disc contact uses the lighter mass (`kBmDiscLightM` 5.5); disc->ball and disc<->disc keep DISC_M 8. Global pace `kBmSimRate` .95 on the fixed-step accumulator | Owner wanted pieces knocked back more without weaker shots; equal masses make disc<->disc independent of mass; slowing the accumulator keeps every step identical, so paths and online sync are unchanged | — |
| D14 | Finger soccer online pre-match picks: each phone picks its own side's team / formation on the intro screens; the pick is the logged `'setup'` move; the match starts when seats 0 and 1 both have one. A phone waiting 75 s after its own setup logs a default setup FOR the missing side (`'for'`); first setup per side in the log wins. Disc felt v4: PF1 0, PF2 3.25 (joint fit of 10 reference tracks) | Both phones derive the start from the same ordered log, so it stays deterministic; screens time out on their own and the fill-in means a match never hangs. Mixed app versions in one room match are not supported (an old phone starts from room prefs at once) | — |
| D15 | Finger soccer v9 reuses the existing shop catalogue ids for the 48 new badges: `club0`..`club39` and `nat20`..`nat27` keep their ids and now point at the owner's Cars / Sport / NX badges (`kBmTeamDefs`). The free ids `club32`, `club33`, `nat26` (`kFreeTeams`) become the NX house badges NX Core, NX Pulse and NX Inferno. Every pre-v9 id that has no v9 badge (the old Luxury `lux*` and remaining national ids) is gone; a saved / synced pick of one resolves to the first team (`bmTeam` fallback) and the shop's default-team rule for picks the player does not own still applies | The gem shop's server catalogue (`nx_catalog` on the auth project) prices and sells by these ids and players' `nx_profiles.data` inventories already hold them. New ids would have needed a catalogue migration and would have orphaned purchases; reusing them keeps every bought slot owned and every free slot free with no server change. Trade-off: a player who bought e.g. `club4` before v9 now owns a different badge (Ferrari) in that slot | — |
| D16 | NEXORA Station UI replaces the whole old UI on top of `arena/integration` (89ee4be). Integration-only pages are re-skinned through `station_compat.dart` adapters instead of being rewritten; games lists come from `kGames`/`kSoloDefs` | Keeps every integration feature (rematch, spectator, safety, ban guard, ledger, Bazaar, victory FX) working with one design language; new games need no UI change | — |
| D17 | Google sign-in: the integration had no Google path; the Station login keeps a visible Google button on Supabase OAuth (`signInWithOAuth(google)`, redirect `nexora://login-callback`, already in the auth project's allow list). Before opening the browser the app reads public `GET /auth/v1/settings`; if `external.google` is false it shows a plain message instead of a failing browser page. Auth provider settings were NOT changed | Project eisstodgncimypdawisy has `external_google_enabled=false` and a client id without a secret; enabling it needs the Google OAuth client secret in Supabase → Authentication → Providers → Google (and the Supabase callback URL in the Google Cloud OAuth client). The button starts working with no app update once that is done | — |
